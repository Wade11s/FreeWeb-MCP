# Architecture

FreeWeb-MCP is a local, single-user Node.js 22.12+ TypeScript MCP server. The public seam is nine MCP tools plus read-only Artifact Resources; stdio is the only transport in the MVP.

## Command line

The package exposes one executable, `freeweb-mcp`. A Commander-based dispatcher owns command routing with strict argument handling: `mcp`, `doctor [--json] [--show-config]`, `init [--json]`, `print-config`, global and command help (`help [command]`, `--help`, `-h`), and the version flags `-v`/`--version`. Running the executable without arguments prints help and exits 0 without creating providers or loading business configuration; the MCP server starts only through the explicit `mcp` command. Unknown commands, unknown help targets, unknown options, and excess positional arguments are usage errors with exit code 1 and diagnostics on stderr. Help and version output stay on stdout.

The published package is CLI-only. `package.json` declares the `freeweb-mcp` bin and no `main`, `module`, `types`, or `exports` metadata, there is no public barrel such as `src/index.ts`, and the internal TypeScript modules the dispatcher imports stay private to the CLI: a consumer import of the package name fails to resolve rather than exposing a supported library API. `npm run verify:pack` holds that boundary against the packed tarball.

`init` is the interactive, terminal-only Initialization command: behind injected-stream seams in `src/init/` it classifies existing configuration, detects providers read-only, and presents one numbered Initialization Step at a time with safe defaults. Provider execution, old → new repairs, the single configuration-write step, and Doctor verification each require their own selection; failed steps offer Retry / Continue / Quit without automatic retries. It installs only a missing certified Firecrawl release where the platform is supported, verifies Firecrawl with an owned loopback Cloud Off process, writes safe configuration atomically with private permissions, backs up damaged files non-destructively, and classifies results into Installed / Configured / Skipped / Pending / Failed with an exit status derived from required-versus-optional semantics. The registered components include every supported provider; Firecrawl is required and TinyFish/ego-lite remain independently skippable. Every combination shares step-level consent, post-execution configuration write, explicitly selected doctor invocation, summary, print-config guidance, and rerun behavior. Required-readiness derivation uses the registered required-component count rather than provider-name branches. Plan items carry a stable `component` / `configuration` / `doctor` stage and components provide their own action labels, so display text and provider ids never control orchestration. Component-declared fixed public phrases feed the central redactor, machine reports are redacted recursively before JSON serialization, and verification timeouts travel through generic detection data, so provider rendering and execution policy remain under `src/init/components/`. A successful final result explicitly says that command success is not readiness of every optional capability. Automatic Firecrawl installation is limited to macOS and Debian/Ubuntu, runs the version-pinned crates.io request `cargo install firecrawl-local --version 0.1.0`, and only after Rust, Cargo, and a C compiler are confirmed present; Initialization never installs those prerequisites, a package manager, Xcode command-line tools, or Chrome/Chromium. Windows and other platforms get detection and manual guidance. Existing provider installations are never upgraded, downgraded, or reinstalled, and `init` never touches other MCP clients' configurations.

The registered TinyFish Initialization component treats the official SDK integration as already included with the package: it performs environment-key presence detection and an explicit Free-attestation handoff only, never global CLI installation or invocation. Its sole possible configuration contribution is a schema-valid `tinyfish.freeOnlyConfirmed` boolean returned after attestation. Missing credentials or attestation are `Pending`; optional `Skipped` and `Pending` do not block the required baseline, while a selected `Failed` operation does. It makes no SDK, wallet, Search, Fetch, or other paid-risk request and does not enable Firecrawl Search Fallback, so `Configured` records prerequisites rather than proving TinyFish readiness.

The optional ego-lite component is a new registered module (`src/init/components/ego.ts` plus one `required: false` registry entry), so the orchestrator has no provider-specific branch. Its supported-platform handoff runs after its Initialization Step is selected through the shared bounded `CommandRunner`: `open <https://lite.ego.app/>` on macOS and `explorer.exe <https://lite.ego.app/>` on Windows. It first asks for handoff consent; declining returns `Skipped` with no opener process before installation, verification, or configuration changes. It never executes a remote install script, strips quarantine attributes, elevates privileges, upgrades an existing app, or imports browser state; the user alone completes GUI onboarding and all Profile/cookie/password/session/bookmark/extension decisions. Command and native Node.js entry probes happen only after a separate explicit onboarding confirmation. Resolved absolute paths flow through the shared detection patch/repair contract, including individually confirmed stale-path old → new changes. Unsupported platforms (including Linux) return `Skipped`; unconfirmed onboarding returns `Pending`; selected opener or verification failures return `Failed` and therefore exit 1. Application installation and these probes are not Browse readiness. Routine tests simulate the opener and Windows platform with fake executables and temporary homes; simulation requires `FREEWEB_INIT_TEST_MODE=1` with `FREEWEB_INIT_PLATFORM=win32`, and production ignores `FREEWEB_INIT_PLATFORM`. No real GUI, installer, or browser data is touched.

The executable entry point is the only code that reads argv, writes to the process streams, or terminates the process; it hands those powers to the dispatcher as an injectable context, isolating Commander's output and exit hooks at the CLI boundary so tests and the MCP stdio stream stay deterministic. The interactive `init` command is the one sanctioned exception for input: its command boundary reads terminal TTY state and hands `process.stdin` to the injected prompt seam, and nothing under `src/init/` touches the real streams. Text prompts use stdout; `init --json` routes all prompts and progress to stderr and reserves stdout for one final versioned report, so JSON interactivity is based on stdin and stderr rather than a redirected stdout. `doctor` and `mcp` load and validate business configuration inside their handlers; `init` classifies it inside its own handler through the `src/init/config-store` seam; help, version, and `print-config` never touch it. `print-config` emits a static executable-native entry whose command is `freeweb-mcp` and whose only argument is `mcp`; deployment must ensure the MCP client process can resolve that executable through its `PATH`, including for GUI or service clients that do not inherit an interactive shell's environment. The `mcp` handler owns runtime creation, stdio serving, signal handling, and the orderly shutdown deadline; stdout stays reserved for JSON-RPC, and startup and shutdown diagnostics go to stderr.

The `doctor` handler renders a grouped human report with required checks, optional capabilities, remediation, and next steps; complete redacted configuration is opt-in through `--show-config`. In `--json` mode it writes one `schemaVersion: 1` document to stdout while retaining `ok` and `checks` and adding stable status, summary, per-check remediation, and next-step fields. An unusable configuration becomes one failed required `configuration` check in either presentation; JSON stdout stays parseable and its human diagnostic goes to stderr. Doctor's Node.js check enforces the `engines.node` floor read from package.json, so the declared minimum has one source. A failed required check exits 1; optional warnings do not. Provider binaries are only spawned with `--version`, and TinyFish readiness is read from configuration, so doctor starts no business provider and makes no wallet or API request.

## Modules

- **FreeWebRuntime** coordinates configuration, providers, URL checks and shutdown. Providers start lazily.
- **ProviderRouter** owns Search/Fetch/Map provider selection, one-alternate fallback, local rate/concurrency budgets, structured attempts and inline output budgets.
- **FirecrawlLocalProvider** owns the local v0.1.0 HTTP contract and its child serve process. The serve process uses loopback, an owned port and FIRECRAWL_CLOUD=off. Unexpected process death invalidates the cached runtime for lazy restart; startup can be aborted during close, and a closed provider cannot revive itself. Crawl marks three consecutive provider refresh failures as failed instead of polling forever.
- **TinyFishProvider** uses only the official SDK Search and Fetch resources with maxRetries: 0.
- **CrawlManager** owns asynchronous Crawl Jobs, checkpoints, pagination, cancellation and terminal Artifacts. An interrupted active Job is lost, never silently resumed.
- **ArtifactStore** writes private local content and exposes freeweb://artifacts/{id} MCP Resources.
- **EgoProvider** owns managed TaskSpace records, native method validation, page evaluation and unrestricted Node execution.
- **MCP server** validates tool input/output with Zod, returns isError for tool failures, and keeps stdout reserved for JSON-RPC.

## Provider routes

| Capability | Primary | Alternate |
| --- | --- | --- |
| Search | TinyFish Search | Explicitly enabled keyless Firecrawl Search |
| Fetch | Firecrawl Local scrape | TinyFish Fetch per failed URL, only when semantics are preserved |
| Crawl | Firecrawl Local | Bounded same-provider behavior; no cloud fallback |
| Map | Firecrawl Local | None |
| Browse | ego-lite | Recovery in the same managed Space; raw scripts are self-managed |

A valid empty result or target HTTP response is not a provider failure. A timeout whose cloud outcome is uncertain is not repeated automatically. Unknown or provider-ignored options are rejected before a request.

## Crawl Job state

Active Jobs are scraping and are checkpointed when provider state changes and when status is read. Writes are serialized per Job with unique temporary files, and close allows two seconds for in-flight reads before marking active work lost. Provider 404 is lost, cancellation tolerates an already missing Job, and compatible next responses are aggregated without dropping earlier pages. Terminal states are completed, failed and cancelled. Process interruption makes an active Job lost. Terminal and lost Jobs have a complete checkpoint Artifact by default retained for 24 hours. Pagination and per-page/total inline truncation never alter the stored full checkpoint. A bounded in-memory terminal set can be reloaded from disk on demand, and expired checkpoints are reclaimed from both memory and disk.

## Browse rounds

A managed browseId maps to one ego TaskSpace. Work and finish run in separate ego Node invocations. Normal rounds finish with the minimal required kept Pages; later rounds claim/take over and adopt them. close finishes with keep: []. Errors and handoff preserve the same Space for recovery and do not create a replacement.

browse_evaluate passes script text as data to page.evaluate. browse_node is registered only when explicitly enabled, receives an unmodified script, and never receives an automatic finish. Its filesystem, process, network, CDP and TaskSpace side effects belong to the caller, so mayHaveLateEffects is always true. Large managed results are written to controlled hand-off files before registration as Artifacts, avoiding truncation in runner output; large structured results use bounded inline budgets and summaries. Managed navigation uses WHATWG parsing with control/backslash/authority-smuggling rejection and HTTP(S)-only targets. Open writes a recoverable placeholder before creating a Space, close/reap finish registered Spaces concurrently with short timeouts, and closed providers reject new work rather than reviving processes.
