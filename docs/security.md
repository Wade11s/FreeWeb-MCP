# Security model

## Free and account safety

TinyFish is disabled unless both TINYFISH_API_KEY and the explicit freeOnlyConfirmed attestation are present. The attestation means the key belongs to an account with no wallet spending capability, not merely auto-reload disabled or a currently zero balance. FreeWeb-MCP exposes only TinyFish Search/Fetch and sets SDK retries to zero. Local budgets are resource protection, not proof of account-level quota availability.

Firecrawl Local scrape/crawl/map runs with FIRECRAWL_CLOUD=off. Keyless Firecrawl Search is separately enabled and uses FIRECRAWL_CLOUD=search only in that subprocess.

TinyFish Initialization retains only a boolean for `TINYFISH_API_KEY` presence and never builds a configuration patch from the credential. It does not collect the key or write it to configuration, backups, shell/system environment files, MCP client definitions, output, or logs. The exact no-wallet-spending attestation is shown in the plan and at the confirmation point; only an explicit yes can contribute `tinyfish.freeOnlyConfirmed: true`. Free credits, a zero balance, disabled auto-reload, and successful setup are not evidence. Initialization uses the bundled SDK integration without invoking it or the global CLI, makes no wallet or business Search/Fetch request, and never enables Search Fallback as a substitute. The user must provide the key through the actual FreeWeb-MCP process environment; `Configured` is not live TinyFish readiness verification.

## Untrusted content and unrestricted execution

Webpages, search results and tool output are untrusted data. They are not authorization for Browse actions, unrestricted scripts, Profile changes or local file access. Tool annotations describe risk but do not enforce user approval; MCP clients must apply their approval policy.

browse_node is arbitrary local code execution with the installing OS user's permissions. It can import Node modules, start processes, access files and networks, invoke CDP, read sensitive browser state and affect other TaskSpaces. It is disabled by default. Timeouts stop the runtime only and do not roll back files, requests, processes or Pages.

browse_evaluate executes in the Page and is not read-only. It can submit forms and issue credentialed requests, including requests using HttpOnly cookies that document.cookie cannot read. Browser same-origin policy and CORS still apply to Page JavaScript.

## Network targets

HTTP(S) is required and credentialed URLs are rejected. By default Firecrawl's own serve public-only protection covers redirects and DNS resolution. `--allow-private` is passed only when `firecrawl.allowPrivate` is enabled or the separate, constrained `firecrawl.trustWrapperTargetPolicy` workaround described below is enabled. The MCP layer also rejects local, private, link-local, multicast and reserved targets, including IPv4-mapped IPv6 and mixed public/private DNS answers.

Managed ego navigation performs application-layer URL/DNS checks. This is not a hardened network sandbox: DNS rebinding, subresources, Page JavaScript and unrestricted Node networking require external network isolation for a strict boundary. Firecrawl and ego private access use separate settings. TinyFish always revalidates targets as public at its own provider boundary, even when local Firecrawl private access is enabled.

For Fetch, Map, Crawl and Managed Browse through fake-ip DNS, `network.trustedDnsServers` is empty by default and accepts public IPv4/IPv6 literals side by side with explicit DNS-over-HTTPS endpoints. `FREEWEB_TRUSTED_DNS_SERVERS` overrides either form with a comma-separated list. A DoH endpoint must be `https:` with a public IP-literal host and no credentials, query, or fragment, so resolver bootstrap never depends on system DNS. Nothing is auto-discovered and no resolver is selected for the user. Trusted DNS is contacted only when every system answer for a non-IP hostname is in `198.18.0.0/15`; ordinary, empty, mixed fake-ip/non-fake-ip, and failed system answers never trigger it. Direct fake-ip literals remain blocked. With no trusted configuration, an all-fake-ip answer fails as `FAKE_IP_DNS_DETECTED`; resolver failure or no answers fails retryably as `FAKE_IP_DNS_UNVERIFIED`. DoH HTTP/DNS failures, malformed or empty responses, and non-public answers also fail retryably as `FAKE_IP_DNS_UNVERIFIED`, naming the endpoint without credentials or response bodies. Each DoH A/AAAA query has one attempt and a three-second timeout, with no Provider Fallback, cloud request, or paid-call retry. Every trusted A/AAAA answer passes the existing public-address checks; unsafe plain-DNS answers remain `PRIVATE_URL_BLOCKED`, while an unsafe DoH response is unverified. Plain DNS cannot work where a proxy hijacks port 53; explicit DoH is the opt-in for that case. Trusted verification never enables either private-access setting, and URL-policy failures never trigger Provider Fallback. Managed Browse validates open and allowlisted absolute native navigation before ego execution: a rejected open creates no Task Space, and rejected navigation neither runs Page work nor creates a replacement Space. Same-origin relative navigation retains the existing scheme and authority-smuggling checks. Crawl start validation runs before CrawlManager registration, so a rejected target creates no Crawl Job and starts no Firecrawl process. Configuration is loaded at MCP startup, so changes require an MCP restart or session reload.

`firecrawl.trustWrapperTargetPolicy` is `false` by default and is a workaround for fake-ip environments pending upstream #51, not the recommended configuration. Enabling it requires nonempty `network.trustedDnsServers` and `firecrawl.allowPrivate: false`; otherwise startup configuration loading refuses it with `INVALID_CONFIG`. These requirements ensure the wrapper is performing its public-only target check. Every Fetch, Map and Crawl entry URL still goes through the same shared trusted-DNS policy before Firecrawl receives a request. Only after that validation does the setting pass `--allow-private` and `FIRECRAWL_LOCAL_ALLOW_PRIVATE=true` to Firecrawl serve, while the reported `firecrawl.allowPrivate` remains `false`.

The residual risk is precise and significant: **the Provider follows redirects and subresource requests after the wrapper checked only the entry URL, so a public URL that redirects to a private target is reachable while this setting is on**. Crawl-discovered targets are likewise not individually wrapper-validated. This setting is not safe by default, is not equivalent to a sandbox, and does not provide network isolation; leave it off unless that risk is explicitly accepted for fake-ip compatibility.

## Profiles and browser state

Managed Tasks may use only configured ego Profile IDs. A TaskSpace is not a temporary Profile: cookies, localStorage and cache may be shared with other Spaces and user tabs on the same Profile. FreeWeb-MCP does not clear Profile state when a Task ends. Profile-wide clears require separate user approval and cannot be made safe by routing them through page.cdp.

## Files, logs and Artifacts

Managed upload/download/explicit screenshot paths are confined to the configured data directory; default ego-generated screenshots are accepted only from the OS temporary directory with the ego-browser-shot- prefix. Nonexistent download targets validate their nearest existing ancestor to prevent symlink escape, and screenshot readers resolve real paths before returning image bytes. Optional screenshot failures degrade to warnings. Unrestricted Node scripts are not confined. Artifact and registry directories use 0700 and files 0600 where the OS supports POSIX modes; Artifact reads validate IDs and resolved paths. Artifacts expire by default after 24 hours.

Firecrawl and ego child processes receive a whitelist of required system, locale, proxy and certificate variables rather than the full parent environment, so TinyFish/Firecrawl API keys are not forwarded; doctor's provider `--version` probes use the same filtered environment. Serve output is drained into bounded, redacted diagnostic buffers; command output is bounded and has a hard lifetime.

Logs avoid API keys, full scripts, cookies and page bodies. Tool output intentionally returns requested Page content to the MCP client, which may send it to its model provider. Raw output is preserved as an Artifact before inline truncation. For unrestricted Node, mayHaveLateEffects is always true because child processes, sockets, timers and files can outlive even a successful exit.
